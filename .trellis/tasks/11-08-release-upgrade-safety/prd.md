# 发布加固：安全升级、故障恢复与发行验证

## Goal

为阶段性发行建立可验证的安全升级与故障恢复闭环，不将无法任意无损降级等同于不安全，
也不通过免责声明或版本规则例外绕过数据保护。本轮以现有 `dev` 的2.0.1候选为准备范围，
发布保持暂停，完整方案通过评审并完成验收后才重新进入发行步骤。

## User Decisions

- 2026-11-08：用户同意已验收的 `dev` 可阶段性合入 `master` 发行，取消对齐结束即3.0.0的预设。
- 用户在了解030迁移的降级限制后暂停发行；随后认可“安全升级、可验证恢复、优先向前修复、
  有限支持降级”的建议，并同意推进独立加固任务。
- 本任务不承诺任意旧版能读取新版数据，不要求完整双向数据库迁移；不得自动恢复旧快照
  而覆盖用户升级后产生的新数据。

## Background And Evidence

- 候选基线为dev `3702f01`，稳定基线为 `v2.0.0` / master `d2d2b0c`。两条历史分叉，
  只读预检发现22个冲突文件，但源码调查确认部分稳定版修复已通过squash保留，不能只凭祖先关系判断丢失。
- 现有030迁移有事务、SQLite备份与失败恢复；rc.1固定fixture的35个迁移/辅助源码与2.0.0一致。
  这证明结构依据可复用，不等于最终安装包已验收或用户原库已验证。
- `research/upgrade-recovery-gaps.md`记录连接清理、备份验证/轮换、中断记录、恢复文件顺序、
  配置自动回写的具体源码缺口。现有发布配置还存在构建时机、tag落点和缺失资产问题。

## Requirements

### R1 兼容承诺与发布范围

- 按实际用户功能、支持的升级来源与已声明对外契约评估版本；内部迁移不自动要求major，
  无损任意降级也不是发行前提。版本号不代替安全验收，不请求用户豁免安全。
- 2.0.1保留为候选，不提前修改应用版本；最终范围若不符合patch语义，报告证据再确认，
  不静默改版、不撤回已完成的安全机制。
- 明确学习数据v1/v2导入、v2导出与旧版读取边界，不声称旧应用支持未来格式。

### R2 可验证的升级保护

- 升级只在恢复点已验证且保护记录成功保存后修改数据；备份/验证失败不迁移、不丢旧恢复点。
- 捕获异常与进程中断都不能导致半完成数据被正常使用或静默重复迁移；恢复失败不因
  待迁移列表为空而被清掉。未知/未来/缺口台账须在业务写入前安全拒绝。
- 保留真实原始错误及所有恢复材料；不能因close、诊断或marker写入的次级错误丢失根因。
- 已成功进入正常运行的升级不能因后续服务故障自动恢复旧快照，避免覆盖新增数据。

### R3 按实际写入范围保护关联数据

- 自动配置归一化回写前保护原字节；保护失败不覆写原配置。规范配置、坏JSON保持已有不破坏语义。
- 数据库以外的笔记附件、脚本文件、配置及session分别说明是否受本次迁移影响，用隔离样本验证。
  不为未修改文件建立无必要的整目录快照，不将SQLite备份或JSON导出宣称为完整profile备份。
- 备份保持本地受保护属性、加密envelope原形；不解密、不写内容到日志、不上传可复用登录态。

### R4 有限恢复与向前修复

- 自动恢复仅处理本次尚未向正常业务开放的失败升级；意外中断默认安全阻止启动，保留状态供受控恢复。
- 提供可复现的本地恢复说明与合成样本演练：先关闭应用、保留当前数据、验证指定恢复点，
  再执行经确认的恢复；不能通过删marker/台账伪装完成。
- 验证后必须有明确解除阻断路径：目标状态已完成时保留当前数据继续；源状态已确认恢复时
  可授权一次新的升级尝试。部分/未知状态继续阻断，不因安全设计导致永久锁死。
- 明确旧恢复点不包含升级后新增记录。使用后问题优先修复版；受控恢复不得假称后续数据无损保留。
- 不向已发布2.0.0追补不存在的兼容能力；新增版本应拒绝自己不认识的未来数据，而不是尝试读取写坏。

### R5 源码集成及发行验证

- 保留2.0.0已发布修复和阶段0–2契约，解决分叉/冲突，最终树重新验收；PR #8不纳入。
- 发布前证明源码、package、CHANGELOG、tag、exe/blockmap/latest.yml对应，缺任一证据停止；
  构建不能自动上传，也不能合并后再次改版本而破坏tag落点。
- 完成隔离Windows的安装、2.0.0升级、数据保留、故障恢复、卸载留数据及重装验证，
  与真实打包程序冒烟分开记录；不可用隔离环境时明确保留发布阻塞。
- 当前仅规划加固，发布保持暂停；实现、独立检查和完整验收通过后另行确认恢复发行。

## Acceptance Criteria

- [x] R1：版本规则与对外兼容矩阵一致，v1/v2/未来导入验证通过，无“迁移必定major/必须接受例外”残留有效约定。
- [x] R2：实际备份可重开校验；备份/磁盘/权限/句柄/记录/恢复故障注入不破坏原数据或丢根因。
- [x] R2：强制结束覆盖写入前、事务中、迁移间、提交后记录未结束；重启可识别，pending为空也不绕过失败状态。
- [x] R3：配置原字节保护与不回写测试通过，合成笔记/图片/脚本哈希与读取通过，敏感值不进日志或资产。
- [x] R4：旧恢复点在隔离副本恢复后可读，当前状态另存；验证目标/源状态后可受控解除阻断，
      错误状态不解锁；升级后新增数据在正常重启/向前修复演练中保留。
- [ ] R5：最终集成树全量自动门、必需CI、独立复核与隔离安装/升级/恢复验收有清晰记录，无残留发布阻塞。
- [x] R5：发布预检/资产哈希/缺资产/不干净/远程查询失败回归通过，未获恢复发行确认时不创建公开Release。
